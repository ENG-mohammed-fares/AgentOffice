# AgentOffice CI/CD release policy

The dedicated `development` branch is the only automatic production release source. Pushes to this branch run the reusable read-only CI and publish the exact tested Windows candidate only after all required tests, committed dependency lock, security audit and integrity checks pass. A higher stable version is required; unchanged versions are skipped, and outdated commits cannot publish. The release job uses a temporary draft to upload and verify assets before automatically publishing it. No main merge or manual approval is needed. Feature branches and pull requests run CI without publication. The historical `develop/v2` branch is untouched.

Update source, release-version.txt and package-lock.json together for each release. Test live authentication and real installed-app upgrades separately; automated fixtures do not prove these paths. Restrict write access to development and prevent force pushes or workflow tampering via repository rules. Admin permissions are required to configure branch protection. The current installer is unsigned. Fix forward with a higher version; never overwrite existing releases. Investigate incomplete drafts manually.

## Separate distribution repository

The public [AgentOffice-Releases](https://github.com/ENG-mohammed-fares/AgentOffice-Releases) repository has been created and contains user documentation. No public installer has yet been published. The existing private release workflow above remains active until the integration candidate is adopted. The new public-channel workflow must pass integrated QA and security gates, verify a trusted signature, and use a scoped publishing credential. Never publish private source, logs, or candidate manifests. Do not embed repository credentials in the client. Test real installation and update migration before public distribution. Documentation-only changes must not bump the version or trigger a new release. See [deferred backlog](DEFERRED.md).
