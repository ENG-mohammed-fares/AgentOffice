# Security Policy

## Supported versions

Security fixes are prioritized for the latest officially published stable AgentOffice release. As of November 25, 2026, that release is v1.6.15. Older versions should be updated to the latest stable release. Development branches and preview builds are not guaranteed ongoing security support.

## Reporting a vulnerability

Please report suspected security vulnerabilities privately. When GitHub private vulnerability reporting is available, use [Report a vulnerability](https://github.com/ENG-mohammed-fares/AgentOffice/security/advisories/new).

If the private reporting form is unavailable, open a minimal GitHub issue requesting a private security contact, without disclosing vulnerability details, exploit code, credentials or affected user information. Do not post security-sensitive findings in public issues, pull requests or discussions.

Include the affected AgentOffice version, operating system, affected component, a concise description, safe reproduction steps using test data, and the potential impact. Redact secrets, personal data, session tokens and other sensitive information. Do not access or modify other users' data, disrupt services, or perform testing on systems without authorization.

## Response and coordinated disclosure

The maintainers aim to acknowledge reports within 7 calendar days, assess severity and coordinate remediation and disclosure. This is a target, not a guaranteed service-level agreement. Remediation timelines depend on severity, complexity and available evidence. Please allow reasonable time for a fix and coordinate publication with the maintainers.

Security fixes will be distributed through the official [AgentOffice releases](https://github.com/ENG-mohammed-fares/AgentOffice/releases). This policy does not establish a paid bug bounty or expand the permissions granted by the repository license.
