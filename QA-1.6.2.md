# AgentOffice 1.6.2 QA candidate

Startup now checks the stable published GitHub update feed before creating the login/workspace window. A small startup window reports the check and download. The verified installer is applied silently and the app relaunches before showing the workspace. A 20-second check timeout, five-minute download timeout or update error opens the installed version to preserve offline access. Downloads finishing later use the existing safe idle/exit installation policy. A single-instance lock prevents concurrent startup update processes. Development builds skip this check.

QA: verify no-update startup, offline startup, slow download, failed install, startup progress, second launch during updating, and a real update from an installed 1.6.2 build to a newer approved stable release. Unit tests simulate the startup decision logic; they do not prove real installer relaunch behavior. No production publishing is authorized by this change.

## Approved post-sign-in loading intro

The approved 3-second HTML/SVG Motion UI preview is embedded locally, preserving the original logo image, background, light ring, panels, loading bar, and keyframe timing. It appears once after successful sign-in, registration, or guest entry, not on failed login or logout. Preview replay controls are removed. The label `Loading agents` is changed to `Loading team` because agents are not connected yet. The bar represents the intro sequence, not measured loading progress. Reduced-motion mode shows the final static state for three seconds. An isolated sandboxed frame reports completion; a 5.5-second fallback prevents a stalled animation from blocking access. Automated Electron tests exercise the transition and reject a spoofed completion message. Real Windows visual QA remains necessary.

## Authentication lifecycle and in-place wait indicators

The approved three-second full-window animation is now reserved for startup (after the pre-launch update gate), successful authentication/registration/guest entry, successful logout, and successful local password recovery. The text reflects each transition; failed authentication and individual OTP steps do not trigger the full intro. Successful recovery returns to the login with the verified address and success notice; logout returns only after local session termination. A compact reusable AgentOffice Orbit SVG spinner is attached to real pending in-app update checks and cleaned up on success or failure. It respects reduced-motion preferences and does not replace or block the workspace. Other future asynchronous features can use the same helper; no artificial wait for synchronous operations. The startup updater retains its own accurate progress window. QA smoke tests cover startup, logout and password recovery transitions. No publication is authorized.
